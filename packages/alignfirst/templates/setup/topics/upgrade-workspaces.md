# Upgrade Multi-Stack Workspaces

This is a manual, coordinated conversion from JavaScript wrappers and legacy configuration to the AlignFirst workspace CLI. Do not install a new CLI over unaccounted old runtime state. No compatibility loader, automatic migration or bulk consumer-edit utility is provided. Work on one approved repository and its participating worktrees at a time. Keep external repositories and the user's companion registry unchanged without explicit authorization.

## 1. Inventory before mutation

Record the installed runtime, CLI and wrapper versions, the main path, `git worktree list --porcelain`, exact paths, branches, locks, dirty files, missing targets and workspace and dev registry entries. Include externally created worktrees and registered orphans. Save the old configuration, wrappers and registry bytes outside removable targets, with appropriate access controls.

Check every worktree for pending finalizers, live spawn PIDs and process groups, command-managed services, containers, volumes, databases, tunnels and name-keyed sidecars. Dead PIDs do not prove external resources are gone. Stop new lifecycle operations during the cutover. Wait for pending finalizers or resolve abandoned ownership explicitly before cleanup.

Agree which data to preserve and where it is backed up. Obtain approval before destructive teardown, volume deletion or worktree removal. Use teardown hooks when an external tool performs deletion; use `workspace remove` for direct removal. Do not use force to bypass locks, shared-target protection or failed cleanup.

## 2. Clean resources with the old installation

While each old recipe and its dependencies still exist, stop services through that worktree's old tooling. Execute the approved purge or teardown for every registered identity, including failed, partial and orphan preparations. Preserve required databases and volumes first. Inspect resources by explicit project names or labels and durable sidecars; record successful cleanup and anything intentionally retained.

Resolve cleanup failures before retiring recipes. For missing targets, use surviving scripts capable of selecting the recorded name from main, or restore the recipe in a safe existing directory. Do not guess a resource name from a colliding basename. Never delete a registry instead of cleaning its resources.

## 3. Convert settings and project scripts

The target file format is in `{{CMD}} setup guide configuration`.

Rename `.alignfirst.json` to `alignfirst.json` or `alignfirst.jsonc`. Move `ticketIdPattern` and the recognized Git settings into `conventions`. Preserve `plans.repositoryFolder` and `plans.autoArchive`, and rename `plans.folder` to `plans.repositoryFolder`. Remove `cli` and the project `portRange`: unknown properties now fail.

When the companion entry selects the old `.alignfirst.json` item, obtain approval, then run `{{CMD}} companion register --item alignfirst=<location>` with the old item's value. The command preserves the registration's directory, other items and profile selection. Then delete the old `.alignfirst.json` key from the entry by hand; the registry ignores it with a warning. Do not leave both extensions in one location. Companions may provide the complete merged recipe and runtime storage. Choose placement through the registration's `defaultLocation` and items (`{{CMD}} setup guide companion`), not through project settings.

Merge any `alignfirst-workspace.json` or `.jsonc` sections into the selected `alignfirst.json` or `.jsonc`, then remove the retired file. Keep one `schemaVersion: 1`.

Name the chosen assistant guide `ASSISTANTS.md`, as `{{CMD}} setup guide assistant-project` describes. Replace a filename-bound registry selection with the logical item: `{{CMD}} companion register --item assistantInstructionsFile=<location>`.

Extract wrapper callbacks into project-owned commands and scripts that follow "Script ABI" in `{{CMD}} setup guide workspace`. Move workspace preparation, file entries, finalize and purge into `workspace`. Move infrastructure setup, run files, input selection and servers into `devServer`. Replace callbacks with command services and explicit log-ready spawn descriptors. A managed environment needs a spawn service. Remove unused wrapper and package dependencies only after their behavior is represented.

For the instructions rename alone, `schemaVersion` remains 1. The `developerInstructions` registry item and the `developer-instructions` command remain deprecated aliases. The configuration fields `developerInstructions` and `assistantInstructionsFile` are both deprecated; the second takes precedence and fails when invalid. Each deprecated spelling emits a `console.warn` diagnostic on stderr. Reads normalize aliases in memory without rewriting files. Reports use only `assistantInstructionsFile`, including `locations` and `selectionOrigins`. This compatibility does not restore retired workspace files, wrappers or runtime layouts.

Move the allocation range and named-port declarations to `devServer.ports`, the sole project range source. Old slot ranges require an explicit agent conversion based on the recorded resources and required pins; no slot migration command remains. `aligndev project free-ports --size <n> --within <first>..<last>` looks up a free block inside the given bounds, without reserving it. Preserve main pins and dedicated ranges where external bookmarks, providers or allowlists require them. Run the inventory doctor after conversion.

Use argv for data-bearing arguments and quoted ABI variables in shell source. Do not interpolate branch or path text into shell source. Use pure idempotent stdin-to-stdout transforms for structured files, conditional deletion and URL preservation. Declare computed or environment run-file inputs; never fingerprint secrets. Rename `ALIGNFIRST_CONTEXT` to `ALIGNFIRST_WORKSPACE_CONTEXT`; no legacy alias is emitted. Use its absolute `runtimeDir` for deliberately owned sidecars, `configurationDir` for helpers beside the selected file, and the optional `companionDir` for companion-owned assets. Missing optional JSON fields are omitted, and unavailable interpolation fails. Neither path changes the command cwd; an orphan purge executes from main with the missing target's identity and runtime. Generated-file entries remain checkout-confined. Port values are available only in dev phases. Test each script's nonzero and signal behavior and propagate failures. Purge must cover the participating resource families from main for missing targets.

The per-repository live-environment cap accepts a literal number or `{ "env": "PROJECT_DEV_LIMIT", "default": 5 }`. Zero or omission means unlimited; an unset variable selects the default. Defined overrides, including empty strings, must be nonnegative safe decimal integers, or a real startup fails before effects. Inspection and cleanup do not resolve overrides. The CLI loads no dotenv files; application scripts may explicitly load their own ignored files. Spawn services may opt into the `error: { "preset": "node" }` common startup heuristics; custom `log` patterns combine with OR. Keep framework-specific markers in custom patterns.

## 4. Prepare the baseline and account for state

Prepare usable effective plans before setup. Project-local plans must exist, be ignored and be untracked by the product repository. Companion plans resolve directly; preserve the selection and old history without unsolicited copying. Linked worktrees must use main's effective target and location. For project runtime placement, add an ignored, untracked `.local-wt/` destination in every worktree. Companion runtime uses one shared external registry and a path-derived runtime directory per real worktree, without checkout `.local-wt` placeholders, registry links or runtime ignore rules. Local Git exclusions are allowed with approval but still change Git metadata. Preserve a tracked `.local` branch-locally.

The new workspace registry is `{ version: 4, storage, workspaces, runtimeOwners }`, with selected-storage ownership, required recipe provenance and optional PID and token preparation ownership per entry. Companion runtime ownership survives teardown as clean retained state; remove and prune retain the deletionPending identity until exact-directory disposal succeeds. Local `runtimeOwners` is empty. Dev storage remains `{ version: 1, servers }`, with retryable `cleanupPending` state; startup claims remain version 1. Version 3, malformed, foreign or unsupported registries and surviving slot state are rejected before writes. Missing ownership beside existing sidecars or runtime data is an accounting failure, not permission to reset. See the [registry contracts](https://github.com/paleo/alignfirst/blob/main/docs/workspace-architecture.md#versioned-registries-and-paths).

Only after every old identity's processes and resources are accounted for may the agent explicitly convert or reset its runtime state. Preserve the old bytes and the resource accounting. A reset is appropriate only when no resource or pending-finalizer ownership depends on that state. Never relabel unknown provenance as defaults, discard failed cleanup or lose live identities to make validation pass. If retained resources require conversion, review the exact new records against the production validator and verify each recorded identity, path and port. Future schema converters are a separate compatibility feature, not part of this initial conversion.

## 5. Cut over commands and instructions

Update every participating branch's scripts, guides, hooks and automation to `{{CMD}} workspace` and `{{CMD}} dev`, or the explicit Bun form `bunx --bun alignfirst`. Remove `aligndev worktree` invocations and wrapper bootstrap paths. Use the selected installed CLI for all children; never invoke a different published kernel during acceptance.

`workspace setup` adopts the current exact Git root. `setup <branch>` reuses a branch; `setup -c <branch> --from <ref> --path <path>` creates at an explicit destination. Ordinary setup waits; detached setup requires `wait`. `dev setup` reconciles ports, files and infrastructure; `dev` or `dev up` starts the declared services. Manifest-free setup is protocol-ready and performs no install, build or start.

External owners run teardown before deletion. `dev down` stops; `workspace teardown` purges and releases state without deleting files; `remove` additionally deletes the protected Git worktree while retaining its branch. Listing is read-only and retains orphan identities for an explicit prune or teardown. Companion teardown retains runtime ownership after releasing resource registrations. After an external Git deletion, an explicit prune disposes that runtime without repeating the purge. Remove disposes the runtime only after Git succeeds; Git or deletion failures retain the deletionPending identity for retry. CLI companion unregister refuses outstanding resources or incomplete disposal, even with force. Clean retained data can remain, with absolute paths reported before automatic discovery is removed. Clean under the old selection before manual placement or registration edits; former arbitrary locations are not rediscovered automatically.

## 6. Validate and recover safely

Use a disposable home and repository first. Validate the merged configuration with the production `config --json` reader, read the effective `workspace --guide`, then exercise main and linked setup, file reconciliation, service readiness, stop, purge and retry. Test orphan cleanup from main before relying on it. Confirm that unrelated edits, shared plans, companion selections and branches survive cleanup. Record the exact checks and the separately unverified deployment, native-agent and model behavior.

On failure, retain files, registry identity, ports and resource evidence. Repair the named configuration, script or path, then retry the exact operation; failed cleanup must finish before setup or start. A registered manifest-backed workspace whose manifest disappears cannot become defaults. Restore its recipe or provide the required main orphan purge. Restore the old CLI, configuration and state only as a coordinated rollback, after checking which new resources have been created. Do not run mixed old and new writers against the same registries.
